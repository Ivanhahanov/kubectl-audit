# Конфигурация (`audit.yaml`)

Почти у каждого поля есть эквивалентный флаг CLI (`kubectl audit scan --help`); флаги переопределяют
то, что задано в файле конфигурации. Исключение — `exclusions` и `components.extra`: у них нет
флага CLI, поскольку их структура не умещается в один флаг (см. соответствующие разделы ниже).
Укажите файл через `--config audit.yaml`. Ничего не обязательно — пропущенные поля откатываются к
встроенным значениям по умолчанию, показанным ниже.

```yaml
target:
  # cluster: только живой кластер через kubeconfig
  # static:  только пути, перечисленные ниже
  # both:    статические пути + живой кластер (по умолчанию)
  mode: both

  # Kube-контекст для использования в режиме кластера. Пусто = текущий контекст.
  context: ""

  # Человекочитаемое имя кластера для поля Target в отчёте и Source
  # каждой находки, вместо необработанного имени контекста выше (которое
  # может быть нечитаемым ARN/UUID облачного провайдера, или просто
  # "current-context", если `context` пусто). Только косметика. Полезно
  # при сканировании нескольких кластеров и архивировании/сравнении их
  # отчётов.
  clusterName: ""

  # Сканировать каждый неймспейс (режим кластера). Установите в false и
  # перечислите `namespaces`, чтобы ограничиться конкретными неймспейсами.
  allNamespaces: true
  namespaces: []

  # Файлы/директории со статическими манифестами для аудита (используется
  # в режиме "static"/"both").
  paths:
    - ./manifests

  # Неймспейсы, которые полностью пропускаются независимо от режима. По
  # умолчанию — эти два (см. Getting Started: Снижение шума), так как в
  # них нет ничего достойного аудита (публичный ConfigMap, объекты
  # Lease). kube-system намеренно НЕ исключён по умолчанию — там часто
  # размещается реальная, подлежащая аудиту инфраструктура третьих
  # сторон; по-настоящему неизбежные находки из базовой инфраструктуры
  # (kube-proxy, статические Pod'ы control plane) вместо этого
  # обрабатываются точечно встроенными исключениями, а не скрытием всего
  # неймспейса. Игнорируется, если `namespaces` выше — непустой allowlist.
  excludeNamespaces:
    - kube-public
    - kube-node-lease

  # Собственные встроенные объекты Role/ClusterRole/*Binding Kubernetes
  # (с префиксом имени "system:") по умолчанию исключаются из находок
  # RBAC, так как они управляются кластером и не могут быть устранены.
  # Установите true, чтобы включить их.
  includeSystemRBAC: false

policies:
  # Дополнительные директории с пользовательскими YAML
  # ValidatingAdmissionPolicy для загрузки вместе со встроенными
  # политиками.
  dirs:
    - ./policies-custom

  # Отключить конкретные встроенные или пользовательские политики по их
  # metadata.name.
  disable: []
  #  - workload.no-latest-tag

  # Установите false, чтобы выполнять только пользовательские политики
  # из `dirs`.
  builtin: true

output:
  json: findings.json
  markdown: report.md
  # CSV, одна строка на находку — для открытия в табличном редакторе. Не
  # записывается, пока не задано (в отличие от json/markdown выше, пути
  # по умолчанию нет).
  csv: ""
  # Разметка вики Confluence Server/Data Center, готовая для вставки в
  # страницу (h2., ||таблицы||, блоки {expand}, ...). Не записывается,
  # пока не задано. Storage Format (XHTML/ADF) из Cloud — другой,
  # неподдерживаемый формат — см. `kubectl audit template dump --format
  # confluence` для встроенного шаблона и confluenceTemplate ниже, чтобы
  # полностью его заменить.
  confluence: ""
  confluenceTemplate: ""
  # Колоризованная (когда это поддерживается получателем) находка с
  # рекомендацией по устранению, за которой следуют таблицы статистики
  # (разбивка по серьёзности, по проверкам, и — если активен
  # compliance.frameworks — итоговая таблица соответствия). "-" означает
  # stdout — для лога CI или локального терминала. Не записывается, пока
  # не задано. См. --output console=... выше и report.RenderConsole.
  console: ""
  # Включать ли рекомендацию по устранению каждой проверки в console
  # (резолвится через ту же базу знаний, что и колонка Remediation в
  # report.md). Включено по умолчанию.
  showRemediation: true
  # Минимальная серьёзность, при которой `scan`/`rbac analyze`
  # завершается с кодом 1: none|low|medium|high|critical.
  failOn: high
  # Минимальная серьёзность, попадающая в findings.json/report.md/CSV/
  # Confluence/console — это только фильтр отображения, не влияет на
  # failOn или итоговые таблицы соответствия (которые всегда видят каждую
  # находку). none (по умолчанию) показывает всё.
  minSeverity: none
  # Пользовательский report.md.tpl (Go text/template). Пусто —
  # используется встроенный шаблон — см. `kubectl audit template dump` и
  # Report Templates.
  template: ""
  # Title/Category/Remediation каждой проверки в отчёте также
  # разрешаются через knowledgeBaseFile (см. ниже) — собственные
  # формулировки организации отображаются здесь так же, как уже
  # отображаются в triage/Jira, без отдельной конфигурации.
  # Язык собственных заголовков/подписей встроенного Markdown-шаблона: en
  # (по умолчанию) или ru. Это не универсальная система i18n — один
  # готовый русский перевод скелета отчёта (см. `kubectl audit template
  # dump --format ru`). Собственные Title/Message/Remediation находки
  # меняют язык только через knowledgeBaseFile (встроенная база знаний по
  # умолчанию уже русская). Игнорируется, если задан `template` выше.
  reportLang: en
  # Кто отвечает за этот отчёт (имя, команда или очередь тикетов) —
  # отображается в заголовочной таблице отчёта, там это чисто
  # информационно. Также используется triage: если указано имя
  # пользователя Jira, каждая задача, созданная triage, автоматически
  # назначается на него (см. Triage > Пользовательские поля). Не
  # задаётся, пока вы сами не зададите; никогда не выводится
  # автоматически.
  owner: ""
  # Как структурирован(ы) раздел(ы) Findings в Markdown-отчёте:
  # check:     группировка по ID проверки/политики, title/remediation
  #            показывается один раз на проверку, за которым следуют
  #            ресурсы, на которых она сработала (по умолчанию).
  # namespace: группировка по неймспейсу/ресурсу вместо этого, полная
  #            детализация на каждую находку — полезно для передачи
  #            по командам/приложениям.
  # both:      вид с группировкой по проверкам плюс компактный индекс по
  #            неймспейсам. На большом отчёте примерно удваивает число
  #            строк находок (каждая находка перечисляется один раз на
  #            каждый вид) — предпочитайте check или namespace по
  #            отдельности, когда находок становится сотни/тысячи.
  reportView: check
  # Схлопывать повторяющиеся по неймспейсам находки проверки в
  # Markdown-отчёте: когда сообщение проверки одинаково для каждой
  # находки (верно практически для всех встроенных проверок VAP/CEL) и
  # она срабатывает на одной и той же паре Kind+Name как минимум в
  # стольких разных неймспейсах — типичная многотенантная форма,
  # например, провизированные Capsule неймспейсы тенантов, все
  # разворачивающие один и тот же манифест — такие находки показываются
  # одной строкой вместо отдельного пункта на каждый неймспейс. Это
  # исключительно вопрос рендеринга Markdown: findings.json/CSV всегда
  # перечисляют каждую находку по отдельности, поэтому гейтинг
  # --fail-on и CI-инструменты не видят разницы. 0 отключает
  # схлопывание.
  namespaceGroupThreshold: 3
  # Расширяет схлопывание namespaceGroupThreshold на имена, которые
  # разделяют форму сгенерированного идентификатора (UUID или другая
  # длинная последовательность hex/цифр), а не только идентичное
  # буквальное имя — ловит, например, сами Namespace-объекты по тенантам
  # с именами вида "usersvs-<uuid>", которые никогда не смогут разделять
  # буквальное имя, поскольку Namespace имеет область видимости
  # кластера. Включено по умолчанию; установите false, чтобы схлопывать
  # только точные совпадения имён.
  groupByNamePattern: true

# Встроенные русские title/description/remediation применяются к каждой
# проверке автоматически (конфигурация не нужна) — см. Triage > База
# знаний. Укажите здесь файл, чтобы исправить одну запись или добавить
# собственные формулировки вашей организации; объединяется поверх
# встроенной базы, поле за полем. Читается заново при каждом запуске,
# пересборка не нужна. Используется и `scan` (текст Remediation в
# консоли/report.md/Confluence выше), и `triage` (создание тикетов в
# Jira, детальный вид в TUI) — одна база знаний, используемая везде,
# независимо от того, настроены ли вообще triage или Jira.
# knowledgeBaseFile: knowledge-base.yaml

compliance:
  # Фреймворк(и) требований для оценки: cis|fstec|nsa|capsule (полный
  # список см. в compliance-mappings/), либо путь к пользовательскому
  # YAML-маппингу. --frameworks в CLI (только для scan) переопределяет
  # это. capsule — собственный чек-лист многотенантности Capsule
  # (github.com/projectcapsule/capsule) этого инструмента, а не внешний
  # стандарт, как три остальных — выдаёт находки только если в
  # кластере/манифестах есть объекты Capsule Tenant.
  frameworks:
    - cis

# Настраивает `kubectl triage` — см. Triage. Поля для учётных данных нет:
# Personal Access Token Jira берётся только из --jira-token или
# $KUBECTL_AUDIT_JIRA_TOKEN, никогда из этого файла.
triage:
  stateFile: triage-state.yaml
  jira:
    baseUrl: ""
    projectKey: ""
    issueType: ""
    # Опционально: extraLabels (статические метки на каждой созданной
    # задаче), customFields (произвольные поля Jira, строковые значения
    # с Go-шаблонизацией) и summaryTemplate/descriptionTemplate (пути к
    # внешним файлам .tpl, полностью заменяющие встроенную структуру
    # задачи) — см. Triage > Пользовательские поля, дополнительные метки
    # и полностью пользовательский шаблон. Всё читается заново при
    # каждом запуске, пересборка не нужна.

# Исключения (waivers) для конкретных пар (проверка, ресурс) — принятый,
# документированный риск, а не незаметный пробел. Только в файле
# конфигурации (флага CLI нет: у правила слишком много структурированных
# полей, чтобы уместить их в один флаг). Подавленные находки никогда не
# отбрасываются: они по-прежнему вычисляются в обычном порядке, а затем
# откладываются в сторону с сохранением причины в отчёте (раздел
# "Suppressed Findings", массив `suppressed` в findings.json) —
# исключаются только из счётчиков Summary, --fail-on, экспорта CSV и
# таблиц оценок соответствия.
#
# Этот список объединяется с (а не заменяет) собственными встроенными
# правилами исключения этого инструмента для известной привилегированной
# инфраструктуры (агент Cilium, prometheus-node-exporter, kube-proxy,
# статические Pod'ы control plane) — установите
# disableBuiltinExceptions: true / --no-builtin-exceptions, чтобы
# отключить их все, либо disableBuiltinExceptionIds (ниже), чтобы
# отключить только одно. См.
# third-party-operators.md#built-in-exceptions-for-privileged-system-infrastructure.
exclusions:
  - # Ограничивает это правило конкретными проверками; опустите (или
    # укажите ["*"]), чтобы применить его ко всем проверкам.
    policyIds:
      - workload.no-latest-tag

    # Требуется хотя бы одно из kind/namespace/name/labels — пустое
    # совпадение отклоняется при загрузке (иначе оно молча подавило бы
    # всё). Все поля, заданные здесь, должны совпасть (И).
    match:
      kind: Deployment          # точное совпадение
      namespace: legacy         # точное совпадение
      name: "legacy-*"          # глоб path.Match; буквальное имя тоже
                                 # работает как точное совпадение
      labels:                   # каждый ключ должен присутствовать с
        team: platform-legacy   # этим точным значением на исходном объекте

    # Обязательно — отображается рядом с каждой находкой, которую
    # подавляет это правило.
    reason: "Legacy app pending migration, tracked in JIRA-1234"

# Отключить отдельные встроенные правила исключения по id (текущие id
# см. в internal/suppress/builtin-exclusions.yaml: cilium-agent,
# prometheus-node-exporter, falco, tetragon, kube-proxy,
# control-plane-static-pods), оставив остальные активными — более
# точечно, чем disableBuiltinExceptions, который отключает их все разом.
# id без соответствующего правила — безобидная операция без эффекта
# (просто предупреждение), а не ошибка.
disableBuiltinExceptionIds: []
#  - cilium-agent

# Расширить встроенный инвентарь компонентов третьих сторон этого
# инструмента (см. internal/thirdparty/components.yaml) — единственный
# способ добавить собственный внутренний оператор/CNI в таблицу Detected
# Components и обнаружение осиротевших/несоответствующих объектов без
# форка или пересборки, что особенно важно для установки через krew
# (там нет файла components.yaml на диске для редактирования — он
# скомпилирован в бинарник). Та же схема, что и во встроенном файле;
# объединяется с ним, а не заменяет его. Добавление записи здесь само по
# себе НЕ создаёт исключение подавления — для этого сопоставьте запись
# категории System с собственным правилом `exclusions` (выше).
components:
  extra: []
  #  - name: InternalWidgetOperator
  #    category: Application       # System | Application (по умолчанию: Application)
  #    group: internal.example.com # группа API CRD, если есть
  #    labels:                     # селектор меток для фактического
  #      app.kubernetes.io/name: internal-widget-operator  # Deployment/StatefulSet/DaemonSet контроллера
```

## Справочник полей

| Поле | Тип | По умолчанию | Примечания |
|---|---|---|---|
| `target.mode` | `cluster\|static\|both` | `both` | `static` выбирается автоматически, если передан `-f` без явного `--mode`. |
| `target.context` | string | текущий контекст | Kube-контекст для режима кластера. |
| `target.clusterName` | string | `""` | Человекочитаемое имя кластера для поля Target отчёта и Source каждой находки вместо необработанного имени контекста. |
| `target.allNamespaces` / `target.namespaces` | bool / []string | `true` / `[]` | Явный allowlist `namespaces` отключает `excludeNamespaces`. |
| `target.paths` | []string | `[]` | Файлы/директории статических манифестов (режим `static`/`both`). |
| `target.excludeNamespaces` | []string | `[kube-public, kube-node-lease]` | См. [Начало работы: Снижение шума](./getting-started.md). |
| `target.includeSystemRBAC` | bool | `false` | Включать объекты RBAC с префиксом `system:`. |
| `target.includeKinds` / `target.excludeKinds` | []string | `[]` | Фильтрует, какие виды ресурсов загружаются в режиме кластера. |
| `target.checkUpdates` | bool | `false` | `--check-updates` в CLI. Живая проверка актуальности EOL/патчей через endoflife.date. |
| `target.readSecretValues` | bool | `false` | `--read-secret-values` в CLI. Разрешает небольшому числу проверок читать значения Secret — см. [Secrets Mode](./secrets-mode.md). |
| `target.requestTimeout` | string (Go-длительность) | `120s` | `--request-timeout` в CLI. Таймаут на каждый запрос к apiserver; `0` отключает его полностью. |
| `policies.dirs` | []string | `[]` | Дополнительные директории `--policy-dir`. |
| `policies.disable` | []string | `[]` | Значения `metadata.name` политик, которые нужно пропустить. |
| `policies.builtin` | bool | `true` | Установите `false`, чтобы выполнять только пользовательские политики. |
| `output.json` / `output.markdown` | string | `findings.json` / `report.md` | Пути вывода. |
| `output.csv` | string | `""` | Путь для CSV (одна строка на находку); не записывается, пока не задан. |
| `output.confluence` / `output.confluenceTemplate` | string | `""` | Путь для вики-разметки Confluence и пользовательский шаблон для неё. |
| `output.console` | string | `""` | Путь для находок с рекомендацией + таблиц статистики; `"-"` — stdout. Не записывается, пока не задан. |
| `output.showRemediation` | bool | `true` | Включать ли рекомендацию по устранению в `output.console`. |
| `output.failOn` | severity | `high` | `none` отключает CI-гейт по коду выхода. |
| `output.minSeverity` | severity | `none` | Минимальная серьёзность, попадающая в вывод — фильтр отображения, не влияет на `failOn`/таблицы соответствия. |
| `output.template` | string | `""` | Путь к пользовательскому `report.md.tpl`; пусто — используется встроенный по умолчанию. См. [Report Templates](./report-templates.md). |
| `output.reportLang` | `en\|ru` | `en` | Язык заголовков/подписей встроенного Markdown-шаблона. Игнорируется, если задан `output.template`. |
| `output.owner` | string | `""` | Кто отвечает за отчёт; если это имя пользователя Jira, triage также назначает на него созданные задачи. |
| `output.reportView` | `check\|namespace\|both` | `check` | Как структурированы разделы Findings в Markdown-отчёте. |
| `output.namespaceGroupThreshold` | int | `3` | Схлопывать повторяющиеся по неймспейсам находки проверки; `0` отключает. |
| `output.groupByNamePattern` | bool | `true` | Также схлопывать имена, разделяющие форму сгенерированного идентификатора. |
| `knowledgeBaseFile` | string | `""` | Путь к файлу с собственными Title/Description/Remediation организации, объединяется поверх встроенной базы знаний field-за-field. Используется и `scan` (console/report.md/Confluence), и `triage` (Jira, TUI) — см. [Триаж: База знаний](./triage.md). |
| `compliance.frameworks` | []string | `[cis]` | По каким фреймворкам производить оценку; см. [Соответствие нескольким фреймворкам](./compliance.md). |
| `compliance.frameworksOnly` | `*bool` | `nil` (см. примечание) | `--frameworks-only` в CLI. Ограничивает находки только проверками, упомянутыми в `compliance.frameworks`. По умолчанию `true`, если `--frameworks`/`compliance.frameworks` заданы явно, иначе `false`. |
| `disableBuiltinExceptions` | bool | `false` | `--no-builtin-exceptions` в CLI.
